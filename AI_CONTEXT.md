## Цель проекта

Лёгкий read-only просмотрщик Markdown-файлов с Python- и C-
TUI-реализациями для Linux и самостоятельной Android-реализацией.

Основной сценарий использования — чтение технической документации и справочных Markdown-файлов с быстрым переходом между разделами через оглавление и поиском по тексту.

## C-версия

В ветке `main` рядом с Python-версией размещена C-реализация,
функционально выровненная с Python-эталоном.

Структура C-версии:

- `c-src/mdview_model.c` и `c-src/mdview_model.h` — UTF-8 документ, Markdown-
  преобразования, source mapping, визуальные строки и поиск;

- `c-src/mdview_c.c` — `ncursesw` TUI, состояние панелей и навигация;

- `tests/c/test_mdview_model.c` — автономные тесты модели без curses;

- `tests/c/test_cli.sh` — проверки CLI и ошибок;

- `tests/compare_models.py` и `tests/fixtures/parity.md` — прямое сравнение
  текста, стилей, source lines и offsets C-модели с Python-эталоном;

- `tests/pty_smoke.py` — UTF-8 PTY smoke-тест TUI, поиска, resize и
  восстановления терминала;

- `Makefile` — сборка `build/mdview-c` и тестов.

Историческая ветка `c-version` с ранним C-портом сохраняется отдельно.

## Android-версия

В `android/` находится самостоятельное приложение Kotlin/Jetpack Compose версии
`0.1.0`, minSdk 28, compileSdk/targetSdk 35. Оно не использует код TUI-версий.

Структура:

- `markdown/` — модель, однопроходный минимальный Markdown-парсер и поиск;

- `data/` — чтение `content://`/`file://` URI и SharedPreferences-хранилище
  позиций с SHA-256 ключом из URI;

- `ui/ViewerViewModel.kt` — состояние документа, оглавления, поиска и
  восстановления при повороте;

- `ui/MdviewApp.kt` — Compose UI, LazyColumn документа, накладное оглавление,
  жесты, поиск и системные темы;

- `MainActivity.kt` — `OpenDocument` picker, `ACTION_VIEW`/Open with и persistable URI access.

Реализованы H1–H6 в документе, H1–H3 в оглавлении, абзацы, списки,
bold, italic, inline/fenced code и визуальное оформление ссылок. Есть поиск с
циклической навигацией и подсветкой, обратная синхронизация оглавления,
жесты открытия/закрытия и позиция для каждого URI. Ссылки пока не открываются;
таблицы, изображения и сложный CommonMark не поддержаны.

При закрытии Android-поиска текущая позиция чтения сохраняется, а запрос и
подсветка очищаются. Длинные fenced code blocks имеют ограниченный внутренний
viewport; навигация поиска прокручивает его к конкретному текущему совпадению.

Внизу главного Android-экрана постоянно зарезервирована отдельная зона высотой
50 dp с локальным `AdBannerPlaceholder`. Это только UX-заглушка: рекламная сеть,
сетевые разрешения, tracking, advertising ID и consent SDK не подключены. Зона
уменьшает высоту области чтения и никогда на неё не накладывается.

Сборка: JDK 17, Android SDK API 35, `cd android && ./gradlew
testDebugUnitTest assembleDebug lintDebug`. APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

## Текущий статус

Проект подготовлен к первому релизу `0.3.0`.

Основная Python-версия работоспособна и используется как текущая эталонная реализация.

C-версия собирается и повторяет текущий пользовательский
функционал Python-версии: CLI, обе панели, оглавление H1–H3, навигацию,
поиск и подсветку, source mapping, resize, минимальный Markdown-рендер,
UTF-8 и восстановление терминала.

Реализованы:

- запуск из командной строки с указанием Markdown-файла;

- TUI на базе `curses`;

- две панели:

  - `Contents`;

  - `Document`;

- оглавление по заголовкам уровней 1–3;

- переключение глубины оглавления клавишами `1`, `2`, `3`;

- навигация по оглавлению;

- переход к выбранному заголовку по `Enter`;

- прокрутка документа;

- переключение панелей по `Tab`; при переходе из оглавления в документ
  выполняется переход к выбранному заголовку;

- Vim-подобная навигация `h/j/k/l`;

- автоматическая синхронизация оглавления с текущим разделом документа;

- корректировка viewport оглавления при смене глубины;

- перенос текста по ширине правой панели;

- связь визуальных строк с исходными строками Markdown;

- перестроение визуальных строк при resize терминала;

- UTF-8, включая русский текст;

- минимальный Markdown-рендер:

  - H1 в uppercase с bold, без `#`;

  - H2 с bold + underline без `##`;

  - H3 с underline без `###`;

  - ссылки в виде `текст (URL)` без атрибутов;

  - inline code, bold и italic остаются без отдельного оформления, их маркеры видимы;

  - простые Markdown-таблицы без строки-разделителя и внешних `|`, с выравниванием колонок пробелами;

  - маркированные списки с `-`, отображаемые с маркерами `◆`, `▸`, `▪` по уровням, и нумерованные списки с маркером вида `1.` до трёх уровней вложенности;

  - перенос длинных пунктов с выравниванием продолжения по тексту пункта;

- базовое отображение code blocks;

- поиск по тексту;

- регистронезависимый поиск через `casefold()`;

- поиск по UTF-8 тексту;

- циклический переход между совпадениями;

- переход к следующему совпадению по `.`;

- переход к предыдущему совпадению по `,`;

- точная подсветка найденного фрагмента;

- поддержка нескольких совпадений в одной исходной строке;

- корректная подсветка совпадений после переноса строк;

- сохранение конкретного поискового совпадения после resize;

- настоящий терминальный курсор при вводе поиска;

- отмена ввода поиска по `Esc`;

## Управление

Основные клавиши:

- `Tab` — переключить активную панель; при переходе из `Contents` в
  `Document` синхронизировать документ с выбранным заголовком;

- `h` — активировать `Contents`;

- `l` — активировать `Document`; при вызове из `Contents` перейти к
  выбранному заголовку;

- `j` / `k` — перемещение вниз / вверх в активной панели;

- `↑` / `↓` — перемещение в активной панели;

- `PgUp` / `PgDn` — перемещение на страницу;

- `Home` / `End` — начало / конец;

- `Enter` — переход к выбранному заголовку или подтверждение поиска;

- `1` / `2` / `3` — глубина оглавления;

- `/` — ввод поискового запроса;

- `.` — следующее совпадение;

- `,` — предыдущее совпадение;

- `Esc` — отмена ввода поиска или сброс текущего поиска;

- `Q` / `q` — выход.

Стрелки и `Tab` работают наряду с Vim-подобной навигацией.

## Важные технические моменты

### Исходные и визуальные строки

Необходимо различать:

- исходные строки Markdown-файла;

- визуальные строки после переноса по ширине терминала.

Навигация, поиск и переходы по заголовкам не должны зависеть от старых экранных координат.

### Resize

Изменение ширины терминала меняет:

- количество визуальных строк;

- положение перенесённых фрагментов;

- экранные позиции поисковых совпадений.

После resize необходимо перестраивать визуальное представление и восстанавливать логическую позицию по исходным данным.

### Поиск

Поиск выполняется по исходному тексту документа.

Текущее совпадение должно хранить:

- индекс исходной строки;

- точный диапазон символов совпадения.

При отображении нужно корректно переводить диапазон исходного текста в одну или несколько визуальных строк.

### Unicode

Русский текст должен отображаться корректно.

Не следует считать индекс Unicode-символа равным экранной колонке.

Нужно учитывать:

- широкие символы;

- combining characters;

- особенности `casefold()`.

Сложные emoji-графемы и символы неоднозначной ширины могут зависеть от конкретного терминала.

### Терминал

Терминал всегда должен полностью восстанавливаться:

- после обычного выхода;

- после внутренних ошибок;

- после отмены режимов ввода.

## Текущие ограничения

Пока не реализованы:

- полноценный Markdown-рендеринг;

- работа мышью;

- изображения;

- переход по ссылкам;

- несколько одновременно открытых документов;

- конфигурационный файл;

- темы;

- плагины;

- редактирование.

Длинные строки внутри fenced code blocks сейчас могут обрезаться по ширине панели.

Совпадение поиска, находящееся в обрезанной невидимой части такой строки, нельзя визуально показать.

Выравнивание Markdown-таблиц через `:---`, `---:` и `:---:` и сложная Markdown-разметка внутри ячеек не поддерживаются.

Task lists, смешанные и сложные вложенные списки не поддерживаются.

Python остаётся эталоном. При изменении его пользовательского поведения нужно
одновременно обновлять C-модель, C-TUI и parity-тесты. C-реализация использует
системные wide-character функции текущей UTF-8 locale; редкие Unicode-
преобразования регистра, расширяющиеся в несколько символов, требуют явной
поддержки в C (сейчас покрыт используемый тестами случай `ß` → `ss`/`SS`).

## Принцип развития Markdown-рендера

При улучшении отображения Markdown приоритет:

- универсальность;

- читаемость;

- работа в максимально широком диапазоне терминалов;

- отсутствие обязательной зависимости от цветов;

- отсутствие обязательной зависимости от italic и других необязательных terminal attributes.

Не стремиться сразу реализовать полный стандарт Markdown.
