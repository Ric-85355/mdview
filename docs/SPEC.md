# Техническое задание
## CLI/TUI-просмотрщик Markdown-файлов

### 1. Назначение программы

Разработать лёгкое консольное приложение для чтения Markdown-файлов (`.md`) в терминале с псевдографическим интерфейсом TUI.

Программа предназначена только для просмотра Markdown-документов. Редактирование файлов не требуется.

Основной сценарий использования — чтение технической документации, инструкций и справочных файлов с быстрым переходом между разделами через автоматически сформированное оглавление.

---

## 2. Запуск программы

Программа запускается из командной строки с указанием Markdown-файла:

`mdview filename.md`

После запуска приложение открывает указанный файл и переходит в полноэкранный TUI-режим терминала.

Если файл не существует, недоступен для чтения или не является обычным файлом, программа должна вывести понятное сообщение об ошибке и завершить работу.

---

## 3. Общий интерфейс

Экран приложения разделён на две вертикальные панели:

- левая панель — оглавление документа;
- правая панель — содержимое Markdown-файла.

Пример:

```text
┌────────────────────────────┬──────────────────────────────────────────────┐
│ Оглавление                 │ README.md                                    │
│                            │                                              │
│ > Установка                │ # Установка                                  │
│   Настройка                │                                              │
│   Сеть                     │ Текст раздела...                             │
│   Samba                    │                                              │
│                            │ ## Настройка                                 │
│                            │                                              │
│                            │ Текст документа...                           │
│                            │                                              │
└────────────────────────────┴──────────────────────────────────────────────┘
 1/2/3 — уровни оглавления    Tab — панель                 Q — выход
```

В нижней строке экрана должна отображаться краткая подсказка по основным клавишам.

---

## 4. Левая панель — оглавление

Оглавление формируется автоматически по заголовкам Markdown:

- `#` — заголовок первого уровня;
- `##` — второго уровня;
- `###` — третьего уровня.

Заголовки глубже третьего уровня в первой версии приложения в оглавлении не отображаются.

Визуально уровни должны отличаться отступами.

Пример:

```text
Установка
  Подготовка
  Настройка
    Сеть
    Samba
Использование
  Основные команды
```

### Режимы отображения

Пользователь может выбирать максимальную глубину оглавления:

- клавиша `1` — показывать только заголовки первого уровня;
- клавиша `2` — показывать заголовки первого и второго уровней;
- клавиша `3` — показывать заголовки первого, второго и третьего уровней.

Переключение режима не должно изменять положение текста в правой панели.

---

## 5. Навигация по оглавлению

Когда активна левая панель:

- `↑` — предыдущий пункт;
- `↓` — следующий пункт;
- `PgUp` / `PgDn` — перемещение по оглавлению на страницу;
- `Home` — первый пункт;
- `End` — последний пункт;
- `Enter` — перейти в правой панели к выбранному заголовку.

Выбранный пункт оглавления должен быть визуально выделен.

Если оглавление не помещается по высоте экрана, оно должно автоматически прокручиваться так, чтобы выбранный пункт оставался видимым.

---

## 6. Правая панель — документ

Правая панель показывает содержимое Markdown-файла.

Для первой версии не требуется полноценный Markdown-рендеринг.

Необходимо корректно отображать обычный текст и визуально различать основные элементы:

- заголовки;
- обычные абзацы;
- маркированные списки;
- нумерованные списки;
- строки кода;
- fenced code blocks — блоки между тройными обратными кавычками.

Markdown-разметка может частично оставаться видимой, если её удаление или полноценный рендеринг существенно усложняет первую версию.

Главное требование — удобочитаемость текста.

---

## 7. Перенос строк

Текст должен автоматически переноситься в соответствии с текущей шириной правой панели.

При изменении размера окна терминала содержимое должно перестраиваться под новую ширину.

Горизонтальная прокрутка в первой версии не требуется.

Для блоков кода допустимо либо переносить длинные строки, либо обрезать их по ширине панели. Конкретный вариант можно выбрать при реализации первой версии.

---

## 8. Навигация по документу

Когда активна правая панель:

- `↑` — прокрутка вверх;
- `↓` — прокрутка вниз;
- `PgUp` — страница вверх;
- `PgDn` — страница вниз;
- `Home` — начало документа;
- `End` — конец документа.

---

## 9. Переключение между панелями

Клавиша:

`Tab`

переключает активную панель:

`Оглавление → Документ → Оглавление`

Активная панель должна визуально отличаться от неактивной, например рамкой, заголовком или другим способом, поддерживаемым терминалом.

---

## 10. Синхронизация оглавления и документа

При выборе заголовка в оглавлении и нажатии `Enter` соответствующий заголовок должен появиться в верхней части или максимально близко к верхней части правой панели.

В дальнейшем желательно реализовать обратную синхронизацию: при ручной прокрутке документа подсвечивать в оглавлении текущий раздел.

Для первой версии обратная синхронизация считается желательной, но не обязательной.

---

## 11. Изменение размера панелей

Желательная функция первой версии:

- `←` — уменьшить ширину левой панели;
- `→` — увеличить ширину левой панели.

Необходимо установить разумные минимальные размеры обеих панелей, чтобы пользователь не мог полностью скрыть одну из них.

Если эта функция заметно усложняет первую реализацию, допускается использовать фиксированную пропорцию, например около 30% ширины для оглавления и 70% для документа.

---

## 12. Работа с терминалом

Программа должна:

- работать непосредственно в текстовом терминале;
- не требовать X11, Wayland или другого графического окружения;
- корректно восстанавливать состояние терминала после завершения;
- корректно обрабатывать изменение размера окна терминала;
- работать с UTF-8, включая русский текст.

---

## 13. Выход из программы

Клавиша:

`Q`

завершает программу.

Допустимо также поддержать:

`Esc`

как дополнительный способ выхода.

После завершения терминал должен полностью вернуться в обычное состояние.

---

## 14. Ограничения первой версии

В первой версии не требуется:

- редактирование Markdown;
- сохранение изменений;
- работа с несколькими открытыми документами;
- файловый менеджер;
- работа мышью;
- поддержка изображений;
- отображение HTML внутри Markdown;
- полноценный Markdown-рендеринг;
- переход по интернет-ссылкам;
- поиск;
- закладки;
- конфигурационный файл;
- темы оформления;
- плагины.

Эти возможности могут быть добавлены позднее.

---

## 15. Технические требования

Предпочтительная реализация:

- Python 3;
- стандартная библиотека `curses`;
- минимальное количество внешних зависимостей;
- возможность работы на Debian/Ubuntu и производных системах.

Желательно, чтобы первая версия вообще не требовала установки Python-пакетов через `pip`.

---

## 16. Требования к структуре программы

На первом этапе допустима реализация приложения в одном основном Python-файле.

Программа должна быть достаточно структурирована, чтобы позднее можно было без полной переработки вынести отдельно:

- загрузку Markdown;
- анализ заголовков;
- модель документа;
- TUI;
- обработку клавиатуры;
- отображение Markdown.

---

## 17. Минимальные критерии готовности первой версии

Первая версия считается работоспособной, если она:

1. запускается с Markdown-файлом в качестве аргумента;
2. корректно читает UTF-8 Markdown;
3. показывает две панели;
4. строит оглавление из `#`, `##`, `###`;
5. позволяет переключать глубину оглавления клавишами `1`, `2`, `3`;
6. позволяет перемещаться по оглавлению;
7. по `Enter` переходит к выбранному разделу;
8. позволяет прокручивать текст документа;
9. переключает панели по `Tab`;
10. корректно работает после изменения размера терминала;
11. корректно завершается по `Q`;
12. после выхода полностью восстанавливает терминал.

---

Рабочее название проекта:
