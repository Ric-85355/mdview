# MDView Web — план реализации для Codex

## Цель

Реализовывать Web-версию MDView поэтапно, не пытаясь сделать весь функционал за одно задание.

Каждый этап должен опираться на документы:

- `docs/MD-WEB-interface.md`
- `docs/MD-WEB-architecture.md`
- `docs/MD-WEB-auth.md`

Web-реализацию размещать в отдельном каталоге `web/`.
Существующий Android/Linux/C-код без отдельного задания не изменять.

## Этап 1. Основа Web MDView

Создать базовую структуру `web/` и фундамент серверной части:

- PHP backend;
- Auth subsystem;
- Repository API;
- Reader subsystem;
- Renderer subsystem;
- единый контракт `DocumentView`;
- Markdown renderer;
- базовый JSON API;
- CSRF-защита;
- конфигурация пользователей и ролей.

На этом этапе не требуется полировать пользовательский интерфейс.

## Этап 2. Repository UI

Реализовать режим Repository:

- выбор репозитория;
- просмотр каталогов;
- переход по подкаталогам;
- поиск по именам файлов и каталогов;
- открытие документа;
- восстановление состояния Repository.

Операции изменения файлов пока можно не реализовывать.

## Этап 3. Reader UI

Реализовать режим Document:

- отображение `DocumentView`;
- верхнюю панель;
- переход обратно в Repository;
- адаптивное отображение на desktop и mobile.

## Этап 4. TOC, поиск и localStorage

Добавить:

- боковую панель содержания;
- уровни TOC;
- переход к заголовкам;
- поиск внутри открытого документа;
- переход между совпадениями;
- сохранение позиции чтения;
- восстановление последнего состояния через `localStorage`.

## Этап 5. Изменение Repository

Добавить операции администратора:

- Upload;
- New folder;
- Rename;
- Move;
- Delete;
- контекстные меню `⋮`;
- обработку конфликтов имён;
- проверку ролей и прав для каждой операции.

## Этап 6. Проверка и укрепление

После реализации основного функционала:

- проверить безопасность путей;
- проверить CSRF;
- проверить авторизацию и роли;
- проверить ошибки API;
- проверить UTF-8, пробелы и русские имена;
- проверить мобильный интерфейс;
- проверить совместимость с существующим `repository-root`;
- добавить/расширить тесты;
- обновить документацию по фактической реализации.

## Правило работы

Каждое задание Codex должно быть ограничено текущим этапом.

Не реализовывать функции следующих этапов заранее, если это не требуется для архитектурной основы текущего этапа.
