# Интерфейс веб-версии MDView

## 1. Общая концепция

Веб-приложение имеет два основных режима:

1. **Repository** — выбор репозитория, навигация по каталогам и выбор документов.
2. **Document** — чтение выбранного Markdown-документа.

Переход между режимами выполняется без необходимости открывать отдельное приложение или вкладку браузера.

Интерфейс должен быть пригоден как для настольного браузера, так и для мобильных устройств.

---

## 2. Режим Document

Режим предназначен непосредственно для чтения Markdown-документа.

### 2.1. Верхняя панель

В верхней части экрана располагаются три основных элемента:

**Слева — Содержание (TOC)**  
Открывает боковую панель с оглавлением текущего документа.

**По центру — Поиск**  
Открывает интерфейс поиска по текущему документу.

**Справа — Repository**  
Переход из режима чтения в режим Repository.

Условная схема:

`[☰ TOC]          [🔍 Search]          [📁 Repository]`

---

## 3. Отображение документа

Основную часть экрана занимает отрендеренный Markdown-документ.

Необходимо поддерживать как минимум:

- заголовки;
- обычный текст;
- маркированные и нумерованные списки;
- жирный и курсивный текст;
- inline code;
- блоки кода;
- ссылки.

Документ должен автоматически адаптироваться к ширине экрана.

---

## 4. Содержание документа

Содержание открывается в виде **боковой панели, выезжающей слева**.

Оглавление автоматически строится по заголовкам Markdown.

Поддерживаются как минимум уровни:

- H1;
- H2;
- H3.

Пользователь может выбирать максимальную отображаемую глубину оглавления: `1 / 2 / 3`.

Дополнительно допускается сворачивание и разворачивание отдельных ветвей оглавления.

Тап по пункту оглавления переводит документ к соответствующему заголовку.

На мобильном устройстве панель содержания временно занимает часть экрана и закрывается после выбора раздела либо отдельным действием пользователя.

На достаточно широком экране в дальнейшем допускается возможность постоянно держать содержание открытым.

---

## 5. Поиск в документе

Поиск выполняется по текущему открытому документу.

Необходимо обеспечить:

- ввод поисковой строки;
- подсветку найденных совпадений;
- переход к следующему совпадению;
- переход к предыдущему совпадению;
- отображение текущего номера и общего количества совпадений, например `3 / 12`;
- автоматическую прокрутку документа к выбранному совпадению.

---

## 6. Запоминание позиции чтения

Позиция чтения каждого документа сохраняется в браузере с помощью **localStorage**.

Ключ позиции должен однозначно определять документ, например сочетанием:

`repository + path + filename`

При повторном открытии документа пользователь возвращается к сохранённой позиции.

На первом этапе синхронизация позиции чтения между разными браузерами и устройствами не требуется.

---

# 7. Режим Repository

Режим Repository предназначен для:

- выбора репозитория;
- навигации по его каталогам;
- поиска документов;
- открытия документов;
- выполнения операций с файлами и каталогами;
- загрузки новых файлов.

Основная область интерфейса строится по принципу файлового браузера.

---

## 8. Верхняя панель Repository

В верхней части располагаются:

**Слева — текущий репозиторий / смена репозитория**

Позволяет выбрать другой доступный репозиторий.

**По центру — поиск**

Предназначен для поиска документов в репозитории.

**Справа — меню `⋮`**

Содержит действия, относящиеся к текущему каталогу.

Первоначально предусматриваются:

- **Новая папка**
- **Загрузить файл**

Условная схема:

`[Repository ▼]        [🔍 Search]        [⋮]`

---

## 9. Навигация по репозиторию

Основная область содержит список каталогов и Markdown-документов.

Пример:

`📁 English                              ⋮`  
`📁 Music                                ⋮`  
`📁 Boats                                ⋮`  
`📄 Present Perfect.md                   ⋮`  
`📄 Reaper mixing.md                     ⋮`

Над списком или другим подходящим способом отображается текущий путь, например:

`Music / Mixing / Reaper`

### Каталоги

Одиночный тап по основной части строки каталога открывает этот каталог.

### Документы

Одиночный тап по основной части строки Markdown-файла открывает документ и переводит приложение в режим **Document**.

Прокрутка списка не должна восприниматься как открытие элемента.

Отдельного режима предварительного выделения файла для его открытия не требуется.

---

## 10. Контекстное меню элемента

Справа от каждого файла и каталога располагается кнопка:

`⋮`

Она открывает меню действий, относящихся только к выбранному объекту.

Архитектурно предусматриваются операции:

- переименовать;
- переместить;
- удалить.

Набор реально реализованных операций может расширяться по мере разработки.

Нажатие на `⋮` не должно одновременно открывать соответствующий файл или каталог.

---

## 11. Возврат из Document в Repository

При переходе из Repository в Document необходимо запоминать состояние Repository.

При возвращении желательно восстановить:

- выбранный репозиторий;
- текущий каталог;
- позицию прокрутки списка.

Таким образом, пользователь после чтения документа возвращается в то же место репозитория, откуда документ был открыт.

---

## 12. Основной принцип интерфейса

Интерфейс не использует схему:

`выбрать объект → нажать Открыть`

Основное действие выполняется непосредственно тапом по объекту:

**каталог → открыть каталог**  
**Markdown-файл → открыть документ**

Дополнительные операции вынесены в меню `⋮`.

Это позволяет сохранить интерфейс простым для мобильного устройства и одновременно удобным для настольного браузера.
